# Архитектурные решения

1. Один Go module и один внутренний domain package, разделённый по задачам на файлы. Отдельных сервисов или универсального repository framework внутри Platform нет. Generated transport и assets — отдельные пакеты без доменной логики.
2. PostgreSQL — источник состояния. Короткие изменяющие транзакции сериализуются transaction advisory lock. Это простой корректный старт для целевой нагрузки 20 сессий и нескольких реплик, но общий lock ограничивает масштабирование. Внешние validators, S3 и NATS не вызываются под этим lock. Метрики и замер нужны перед переходом к более мелким блокировкам.
3. Конфигурации — versioned JSONB с JCS hash; состояния, leases, роли, idempotency и ключевые связи — отдельные таблицы/ограничения. Опубликованные версии и plan защищены также DB triggers.
4. Outbox/inbox дают at-least-once доставку с идемпотентным эффектом. Broker dedup не заменяет DB constraints. Неподтверждённый результат старой попытки сохраняется как диагностика.
5. Verdict доверяется оценщику после проверки schema/context/manifest hash и обязательных правил агрегации. Platform не выполняет бизнес-assertions и не вычисляет ML scores.
6. Прозрачные opaque BFF sessions; identity — issuer/subject. Local login не включается автоматически и запрещён production-конфигурацией.
7. Signed upload пишет staging; финальный объект создаётся только из проверенных байтов. Это закрывает возможность перезаписать evidence повторным PUT после регистрации.
8. Seed имеет диапазон безопасного JSON integer. Runtime plan передаётся JSON bytes, чтобы не добавлять преобразование чисел через protobuf Struct. Validation subset использует Struct как явно отмеченное предложение до получения provider IDL.
9. Миграция 001 — создание первой схемы. Автоматической down-миграции с удалением данных нет; rollback после эксплуатации делается через проверенный restore. Любая следующая миграция должна быть отдельным versioned файлом с процедурой отката; текущий migrator намеренно принимает только schema version 1.
10. Compose принадлежит только Platform. Общие папки репозитория и код других владельцев не меняются. Полная сквозная приёмка и замер голосовых испытаний требуют их реализации и согласования контрактов.
