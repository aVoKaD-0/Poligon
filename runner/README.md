# Runner

Runner исполняет тестовые сессии Poligon. Он получает задания Platform из NATS JetStream, проверяет зафиксированный план запуска, ведёт сессию под арендой (lease), направляет вызовы инструментов в CRM Environment и регистрирует журналы в Platform.

Движок управляет диалогом через интерфейс симулятора клиента и адаптер проверяемого агента. Слоты воркера ограничивают число одновременных сессий. Platform назначает попытки и принимает терминальные события, а Environment изолирует данные CRM каждой попытки.

## Требования

- Go 1.27.2 или новее для сборки из исходников. Для сборки и запуска контейнера нужен Docker.
- Platform с доступным gRPC Control и настроенными потоками NATS JetStream.
- HTTP API Environment и хранилище, доступное Runner по подписанным URL Platform.

## Локальный запуск

Поднимите Platform, JetStream и Environment по [закреплённым версиям](docs/integration.md#версии). Из корня репозитория выполните:

```sh
cd runner
go build ./...
```

Передайте процессу настройки из [.env.example](.env.example). Для локального Control без mTLS требуется токен Platform. Если NATS требует аутентификацию, задайте имя и пароль сервисного пользователя Runner. Укажите адреса зависимостей, доступные с хоста Runner. Подробности и команды для Docker приведены в [руководстве по разработке](docs/development.md).

```sh
go run ./cmd/runner
```

## Тесты

Из каталога `runner` выполните `go test ./...`. Дополнительные проверки и сценарии с реальными зависимостями описаны в [документации по разработке](docs/development.md#тестирование).

## Текущие ограничения

Для сквозного прогона нужны API симуляции и оценки Intelligence, финализация попыток Environment и согласованный протокол агента. В локальном режиме Runner принимает задания и может вернуть `DEPENDENCY_UNAVAILABLE`. В production потребитель заданий выключен до подключения симулятора. Голосовой WebSocket поддерживает обмен PCM-кадрами. Голосовой сценарий требует интеграции с Intelligence.
