# Стартовый каталог v1.0.0

Все люди, адреса и заявки вымышленные. Бизнес-дата фиксирована (20.11.2026),
не привязана к сегодняшнему времени компьютера. Машинные определения хранятся
в fixtures/scenarios; эталонный generator — scenarios.catalog.

| ID | Исходные условия и цель клиента | Проверяемый результат | Семейство / сбой |
|---|---|---|---|
| create | Нет заявок; запись на Учебную 1, 18:00–19:00 | Одна активная заявка правильного клиента/адреса/даты/времени | booking; без сбоя |
| change-address | Есть order-existing; изменить адрес на Учебную 2 | Та же заявка, новый адрес, прежние клиент и notes | address-update; без сбоя |
| reschedule | Есть order-existing; перенести на 19:00–20:00 | Та же заявка с новым временем | rescheduling; без сбоя |
| cancel | Есть order-existing; отменить её | Ноль активных, нужная заявка cancelled | cancellation; без сбоя |
| ambiguous | Клиент говорит только «вечером»; дату/окно сообщает после вопроса | Одна заявка с уточнённым временем; вопрос проверяется advisory | clarification; без сбоя |
| unavailable | Единственное приемлемое окно помечено недоступным; замены запрещены | Заявка не создана | slot-unavailable; бизнес-ограничение, не внесённая поломка |
| timeout-after-save | Нужна одна заявка; Environment должен сохранить и вернуть 504 один раз | Ровно одна корректная активная заявка | retry-duplicate; declarative timeout_after_save |
| repeat | Клиент повторяет просьбу и явно не хочет вторую заявку | Ровно одна корректная активная заявка | retry-duplicate; повтор поведения клиента, без искусственного сбоя |

У каждого сценария конечная последовательность допустимых реплик, intent каждого
шага, max_turns, constraints, allowed_outcomes и termination=script_exhausted.
Свободные альтернативные бизнес-исходы не выводятся из текста: в MVP один явно
заданный ожидаемый результат на определение. Отсутствие вопроса останавливает
ambiguous с причиной clarification_not_observed; фактический результат оценивается
как обычно, эвристика вопроса отдельно. Содержание подтверждений не интерпретируется
как произвольная смена цели.

Локальные вариации меняют каталог формулировок и согласованный запрошенный адрес.
Модельные вариации ограничены выбором утверждённых формулировок. Другие параметры
пока задаются автором нового валидируемого Scenario. Семейства для split сохраняются.

Три сценария с существующей заявкой локальны: pinned Runner/Environment не умеют
инициализировать orders. Мост Platform отклоняет их, а не обещает готовую интеграцию.
